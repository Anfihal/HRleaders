
# <HRleaders> — отраслевой агрегатор ИТ-вакансий с подтверждаемым профилем

Веб-сервис для подбора ИТ-специалистов, в котором соискатели автоматически категоризируются по объективно подтверждённому профилю, а работодатель сам находит нужную категорию и выходит на конкретного кандидата с вакансией и заработной платой.

## Актуальность

Существующие площадки поиска работы универсальны и уже не решают задачу эффективно ни для работодателя, ни для кандидата. Работодатель вручную фильтрует сотни нерелевантных откликов, а кандидат откликается вслепую и не получает обратной связи.

В ИТ-отрасли проблема усугубляется тем, что формальное резюме фиксирует стек и места работы, но не подтверждает практическую компетентность. Отраслевая специфика — стек, грейд, роль в команде, формат работы — на универсальных платформах не формализована.

Отдельный сервис, созданный под ИТ и говорящий с обеими сторонами на профессиональном языке, способен повысить точность подбора и сократить его сроки. Дополнительное преимущество — подтверждаемость квалификации на основе данных Федерации спортивного программирования (ФСП).

## Решение

Мы разрабатываем цифровую платформу — отраслевой агрегатор вакансий для ИТ-специалистов с обратной механикой подбора:

- соискатели автоматически категоризируются по объективно подтверждаемому профилю;
- профиль обогащается достижениями из информационных систем ФСП;
- работодатель ищет кандидатов не по ключевым словам, а по подтверждённым категориям;
- работодатель сам выходит на конкретного кандидата с вакансией и заработной платой.

## Ключевые возможности

### Для соискателя
- Создание профиля ИТ-специалиста.
- Автоматическое обогащение профиля достижениями ФСП: дисциплины, соревнования, результаты, роли, разряды.
- Категоризация по стеку, грейду, роли в команде и формату работы.
- Возможность конвертировать опыт соревновательного программирования в карьерное преимущество.
- Прозрачная обратная связь от работодателей.

### Для работодателя
- Поиск кандидатов по формализованным ИТ-категориям.
- Фильтрация по подтверждённым достижениям и практическим навыкам.
- Снижение количества нерелевантных откликов.
- Прямой выход на кандидата с вакансией и зарплатой.
- Экономия времени технических специалистов на первичный скрининг.

### Интеграция с ФСП
- Получение данных о достижениях участников соревнований.
- Структура данных: дисциплины, соревнования, результаты, роли, разряды.
- API и/или тестовый мок-сервис ФСП.
- Автоматическое обогащение профиля кандидата.

## Как это работает

1. Кандидат регистрируется на платформе и заполняет ИТ-профиль.
2. Сервис через API ФСП подтягивает подтверждённые достижения участника.
3. Алгоритм матчинга и категоризации формирует объективный профиль кандидата.
4. Работодатель ищет нужную категорию специалистов.
5. Работодатель выбирает конкретного кандидата и отправляет ему вакансию с заработной платой.
6. Кандидат получает релевантное предложение и обратную связь.

## Архитектура

```text
            браузер
               │  same-origin, сессия в HttpOnly-cookie
┌──────────────▼──────────────┐
│ front-end (nginx)           │  Vue 3 SPA, /api → back-end
└──────────────┬──────────────┘
               │ REST /api/v1
┌──────────────▼──────────────┐      ┌──────────────────────┐
│ back-end (FastAPI)          │ HTTP │ API ФСП / mock-fsp   │
│ identity · talent · fsp ·   ├─────►│ (FastAPI, Bearer)    │
│ hiring · analytics          │      └──────────────────────┘
└──────────────┬──────────────┘
               │ SQLAlchemy 2, Alembic
        ┌──────▼──────┐
        │ PostgreSQL  │  данные + справочники и правила скоринга
        └─────────────┘
```

- Back-end разделён на bounded contexts (DDD): `identity`, `talent`, `fsp` (anti-corruption layer над API ФСП), `hiring`, `analytics`. В каждом контексте есть `domain`, `ports` (интерфейсы), `use_cases` и инфраструктура. Зависимости собираются через DI FastAPI.
- Бизнес-правила хранятся в БД, а не в коде. Это баллы за результаты, коэффициенты уровней соревнований, пороги уровней подтверждения и сопоставление дисциплин ФСП с категориями платформы.
- Ошибки типизированы и отдаются в едином формате `{"error": {"code", "message", "details"}}` с корректным HTTP-статусом. Вся валидация выполняется на сервере.
- Подробности: [`docs/mvp-plan.md`](docs/mvp-plan.md) (гипотезы H1–H6, контексты, план), [`back-end/README.md`](back-end/README.md), [`front-end/README.md`](front-end/README.md).

## Технологии

Новый клиент Flutter (web / Android / iOS): [`flutter-app/README.md`](flutter-app/README.md).
Демо включается явно; по умолчанию клиент использует существующий API.

- Frontend: Vite, Vue 3, Nuxt UI, Tailwind CSS 4, Sass, TypeScript, Pinia, Vue Router; тесты — Vitest и Playwright.
- Backend: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, Pydantic; тесты — pytest на SQLite и PostgreSQL.
- База данных: PostgreSQL.
- Интеграция: REST API ФСП, mock-сервис `back-end/mock_fsp`.
- Инфраструктура: Docker, Docker Compose, GitHub Actions.
- Redis и ML-сервис в MVP не используются: ни одному сценарию MVP они не нужны (см. `docs/mvp-plan.md`).

## Быстрый старт

### Требования

- Docker и Docker Compose
- Node.js 20.19+ и Python 3.12+ (если запуск без Docker)

### Запуск через Docker

```bash
cp .env.example .env              # заполните пароли и секреты (openssl rand -hex 32)
docker compose up --build -d      # миграции применяются при старте API
docker compose run --rm seed      # демо-данные (идемпотентно)
```

После запуска:

- Приложение: http://localhost:8080. Вход: работодатель `hr@radius-soft.example`, кандидаты `*@mail.example` (например, `daria.orlova@mail.example`). Пароль — `SEED_DEMO_PASSWORD` из `.env`.
- Документация API: http://localhost:8080/api/v1/docs

### Запуск без Docker

Back-end и mock ФСП описаны в [`back-end/README.md`](back-end/README.md), front-end — в [`front-end/README.md`](front-end/README.md).

## Переменные окружения

Docker Compose читает корневой `.env` (шаблон — [`.env.example`](.env.example)):

| Переменная | Назначение |
|---|---|
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | база данных |
| `JWT_SECRET` | подпись сессий, не короче 32 символов |
| `FSP_API_TOKEN` | общий токен API и мока ФСП |
| `SEED_DEMO_PASSWORD` | пароль демо-аккаунтов |
| `AUTH_COOKIE_SECURE` | `false` только для HTTP на localhost |
| `NATS_TOKEN` | секрет приватного транспорта API/worker (JetStream) |
| `FRONTEND_PORT`, `LOG_LEVEL` | порт приложения и уровень логов |

Для запуска без Docker есть `back-end/.env.example` и `front-end/.env.example`. Секреты в репозитории не хранятся.

## Проверки

CI (`.github/workflows/ci.yml`) на каждый pull request запускает:

- back-end: ruff, mypy и pytest на SQLite и PostgreSQL, включая проверку миграций upgrade → downgrade → upgrade;
- front-end: eslint, vue-tsc, Vitest и сборку;
- e2e: Playwright на мигрированной и заполненной демо-данными базе с mock ФСП;
- сборку Docker-образов.

Для подготовки презентации ФСП доступны сбор Git-статистики и анализ исходного
PPTX: [инструкция и ограничения](docs/presentation.md). Итоговая презентация
требует оригинального шаблона, который пока отсутствует в репозитории.

## Интеграция с ФСП

Сервис использует API или тестовый мок-сервис ФСП для получения данных о достижениях участников.

Пример структуры данных:

```json
{
  "participant_id": "123",
  "disciplines": ["алгоритмическое программирование"],
  "competitions": [
    {
      "name": "Чемпионат ФСП",
      "date": "2025-01-15",
      "result": "призёр",
      "role": "участник",
      "rank": "кандидат в мастера спорта"
    }
  ]
}
```

На основе этих данных профиль кандидата получает подтверждённые категории и дополнительные ориентиры для работодателя.
