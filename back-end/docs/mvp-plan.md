# HRleaders MVP — продуктовый разбор и план

Документ фиксирует результат погружения в задачу (issue #1), бизнес-гипотезы MVP и
последовательный план реализации. Источники истины: issue #1, `Arch.md`, `README.md`.

## 1. Кто пользователи и какие у них боли

Подтверждено `README.md` / `Arch.md`: продукт — **отраслевой агрегатор ИТ-вакансий с
подтверждаемым профилем** для экосистемы Федерации спортивного программирования (ФСП) и
HR-сообщества («Союз HR ФСП»). Механика подбора — **обратная**: работодатель сам выходит на
кандидата с вакансией и зарплатой.

| Пользователь | Боль (из README) | Где теряется время / данные |
| --- | --- | --- |
| HR / рекрутер работодателя | Ручная фильтрация сотен нерелевантных откликов | Excel-выгрузки с job-сайтов, ручной скрининг, техлид тратит часы на первичное собеседование |
| Техлид / нанимающий менеджер | Резюме не подтверждает практическую компетентность | Тестовые задания и скрининги «вслепую» |
| Руководитель HR | Нет измеримой воронки подбора | Метрики собираются вручную по чатам и таблицам |
| ИТ-специалист / спортсмен ФСП | Откликается вслепую, нет обратной связи; достижения в соревнованиях не конвертируются в карьеру | Достижения лежат в системах ФСП и не видны работодателю |

## 2. Бизнес-гипотезы MVP

| # | Проблема | Гипотеза | Сценарий | Экран | API | Проверка (метрика README) |
| --- | --- | --- | --- | --- | --- | --- |
| H1 | Резюме не подтверждает компетентность | Достижения ФСП, подтянутые автоматически, повышают доверие к профилю | Кандидат указывает ID участника ФСП → профиль обогащается дисциплинами, соревнованиями, результатами, разрядами | «Мой профиль» | `POST /api/v1/candidates/me/fsp-sync` | Доля профилей, обогащённых данными ФСП |
| H2 | Ручная фильтрация откликов | Поиск по подтверждённым категориям (дисциплина × уровень) быстрее поиска по ключевым словам | Рекрутер фильтрует «Алгоритмическое программирование, уровень ≥ Продвинутый, Python, удалёнка» | «Кандидаты» | `GET /api/v1/candidates` | Время подбора, конверсия просмотр → предложение |
| H3 | Кандидат откликается вслепую | Прямое предложение с вакансией и зарплатой даёт высокий отклик | Рекрутер отправляет предложение из карточки кандидата | «Карточка кандидата», «Предложения» | `POST /api/v1/offers` | Количество прямых контактов, доля принятых |
| H4 | Нет обратной связи | Обязательная причина отказа делает процесс прозрачным | Кандидат принимает или отклоняет предложение с причиной | «Мои предложения» | `POST /api/v1/offers/{id}/accept|decline` | Доля предложений с ответом |
| H5 | Нет измеримой воронки | Встроенная аналитика воронки заменит ручные отчёты | Руководитель HR видит воронку и распределение талантов | «Обзор», «Аналитика» | `GET /api/v1/analytics/overview` | Все метрики успеха README |
| H6 | Достижения не конвертируются в карьеру | Видимый «путь до следующего уровня» мотивирует участвовать в соревнованиях ФСП | Кандидат видит, сколько баллов не хватает до следующего уровня | «Развитие» (`/me/development`) | входит в профиль | Рост доли кандидатов уровня ≥ Продвинутый |

**Гипотезы, сознательно отложенные (YAGNI):** отдельный модуль обучения (заменён блоком
«Развитие» в профиле, H6), лента HR-сообщества, уведомления, ML-разбор резюме, Telegram-бот
из `Arch.md`. Для них нет подтверждённых требований в README/Roadmap MVP; архитектура
(bounded contexts) позволяет добавить их отдельными модулями.

## 3. Bounded contexts

| Контекст | Ответственность | Основные сущности |
| --- | --- | --- |
| `identity` | Регистрация, вход, роли (`candidate`, `employer`) | `User`, `Role` |
| `talent` | Профиль ИТ-специалиста, обогащение данными ФСП, категоризация, поиск | `CandidateProfile` (агрегат), `FspAchievement`, `TalentCategory`, `ScoringRules` |
| `fsp` (ACL) | Интеграция с API ФСП / мок-сервисом | `FspParticipant` DTO, порт `FspGateway` |
| `hiring` | Вакансии и прямые предложения с зарплатой, обратная связь | `Vacancy`, `Offer` (агрегат), `OfferStatus`, `SalaryRange` |
| `analytics` | Read-model воронки подбора | `HiringFunnel`, `TalentDistribution` |

Категоризация — доменный сервис `talent`: баллы за результат × коэффициент уровня соревнования
+ баллы за спортивный разряд → уровень подтверждения. **Все веса и пороги — справочные данные
в БД** (`scoring_rules`, `fsp_disciplines`), а не константы в коде.

## 4. Стек (решение)

- Backend: Python 3.12+, FastAPI, SQLAlchemy 2, Alembic, Pydantic Settings, PostgreSQL.
- Frontend: Vite, Vue 3, Nuxt UI (Vue-режим через `@nuxt/ui/vite`), Tailwind CSS 4, Sass, Pinia, Vue Router, TypeScript.
- Мок ФСП: отдельное FastAPI-приложение `back-end/mock_fsp`.
- Инфраструктура: Docker Compose (postgres, backend, mock-fsp, frontend), GitHub Actions CI.
- Redis и ML-сервис из README не добавлены: в MVP нет сценария, которому они нужны.
